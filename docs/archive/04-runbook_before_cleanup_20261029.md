> 设计存档：本文件记录实施前的方案，部分环境、文件名和步骤已调整。当前使用方法以 [USAGE.md](../../USAGE.md) 为准；实测版本见 `configs/environments.lock.json`，实测结果见运行目录的 `deliverables/report.md`。

实施按“先验证参考音色，再验证换风格，最后集成和扩展”的顺序推进。每一步都保留可听的中间结果；出现质量问题时先定位阶段，再调整参数。

第一轮只需要一个歌曲样本和一个目标人物。原曲与参考录音可以来自不同文件；目标人物不必唱同一首歌。参考片段先选约 10–15 秒单人清晰录音，含背景音乐时先分离，有干净歌声时优先采用。

素材登记时记录文件来源、版本、原始时长、参考片段位置和音频哈希。歌曲宝页面可以作为手工样本入口，实际下载后再确认文件完整、歌词与该演唱版本一致；首版不开发抓取器。[歌曲页面示例](https://www.gequbao.com/music/6762)

歌词准备保留实际唱出的重复句和段落，删除制作信息与 LRC 时间标签，使用与谱结构对应的段落标记。原始 LRC 单独保留，避免失去核对依据。原曲歌词时间不能作为生成歌曲的混音时间。

实施里程碑按以下顺序完成。表中的“通过”是继续实验的条件，不是本轮已完成的状态。

| 里程碑 | 工作 | 产物与通过条件 |
| --- | --- | --- |
| M0 素材与环境 | 准备一首歌、一份歌词、一段参考；逐个环境 preflight | 素材清单、环境和模型锁定清单；短音频能被各模块读取 |
| M1 换声探针 | 分离原曲 20–30 秒人声，运行 Seed-VC | 探针音频能辨认歌词、旋律和目标音色，明显失真可定位 |
| M2 风格转换 | 原曲转录、核对 ABC 与歌词、YuE2 生成 | 原曲旋律可辨认，目标风格明显，生成未截断 |
| M3 分离对照 | 分离 YuE2 输出，直接重混双轨 | 确认分离产生的音质损伤和伴奏人声残留 |
| M4 完整转换 | 用 YuE2 的短段人声再验证，之后转换完整人声并混音 | 全曲无明显漂移或接缝，输出完整 |
| M5 自动化 | 在已成功的调用路径外封装适配器、状态和恢复 | 更换参考录音只重跑必要阶段；失败后可恢复 |
| M6 最小对照实验 | 固定其余变量比较参考片段与推理步数 | 形成可复查的听感和耗时记录 |

M1 失败时先检查参考素材、源人声纯度和 F0 条件，不立即增加训练。使用说话参考时，重点听高音和长音；成功与否需要实测，零样本能力不保证任何参考录音都能达到稳定音色。

M2 调用现成上游入口，未来适配器只负责准备这些调用所需的文件。

| 模块 | 上游入口 | 本项目明确传入的内容 |
| --- | --- | --- |
| SheetSage2 | models/SheetSage2/infer.py | 原曲路径、输出目录、melody-only |
| YuE2 | examples/generate.py | request 文件、abc-file、cot=melody、输出目录 |
| 双轨分离 | audio-separator CLI | 生成歌曲、固定模型文件名、输出格式和增益配置 |
| Seed-VC | inference.py；单独试听可用 app_svc.py | source、target、output、F0 参数及选定权重配置 |
| 混音 | 后续项目 audio 模块，初期可用现有音频工具验证 | 明确的输入轨、采样率、延迟、增益、输出长度 |

YuE2 request 使用官方已有的 style、lyrics、cot、seed 字段，ABC 通过对应入口提供。转录得到的 ABC 先核对旋律、段落顺序和缺失部分，再生成完整歌曲。[官方调用流程](https://github.com/multimodal-art-projection/YuE/blob/main/docs/covers.md)

首个目标风格可以使用“中文爵士小编制，钢琴、低音提琴和轻刷鼓，单人主唱、人声靠前、少量混响”。它是可调整的实验提示，不是模型严格执行的硬约束。首轮固定一个 seed；若生成质量不合格而换 seed，必须把所有尝试纳入运行记录，不能只保留最好听的一次。

M3 使用 BS-RoFormer 文档示例权重 `model_bs_roformer_ep_317_sdr_12.9755.ckpt`，先输出人声和伴奏两轨。分离工具可能在输出阶段做归一化，适配器需要核对并记录具体设置；否则直接重混的误差会同时混入电平变化。[工具说明](https://github.com/nomadkaraoke/python-audio-separator)、[输出处理源码](https://github.com/nomadkaraoke/python-audio-separator/blob/main/audio_separator/separator/common_separator.py)

M4 首轮固定以下 Seed-VC 配置，避免同时改变音高、时长和音色。

| 参数 | 首版值 | 调整条件 |
| --- | --- | --- |
| f0-condition | True | 歌声转换保持开启 |
| auto-f0-adjust | False | 首版不自动向参考录音音域移动 |
| semi-tone-shift | 0 | 若后续整体移调，需同步考虑伴奏 |
| length-adjust | 1.0 | 首版不主动改变演唱速度 |
| diffusion-steps | 30 | 参考与源人声质量合格后，再与 50 步对照 |
| inference-cfg-rate | 0.7 | 先固定，不做大范围搜索 |
| source | YuE2 分离人声 | M1 探针除外 |
| target | 已选定的清晰参考片段 | 内容哈希进入换声缓存键 |

这些参数来自[官方歌声推理说明](https://github.com/Plachtaa/seed-vc#usage%EF%B8%8F)。模型内部已包含长音频处理，首版复用其实现；只有观察到边界问题时再设计外部分块。外部分块必须保存起始采样点，并在原位置重建，包括所有停顿。

完整转换完成后，先核对起音、句末和长停顿，再执行混音。只在有证据时校正固定延迟；不能把不同长度的音轨简单截为一样长就认为已经对齐。首版不额外加入复杂母带链路，先使音量合理、峰值受控、听感连续。

M5 的最小开发顺序如下，不必先建立完整服务框架。

1. 实现音频探测和请求校验，固定文件命名、采样率与时间轴记录。
2. 包装已手工验证成功的四个模型入口，保留原始日志与输出。
3. 实现混音及 A／B／C 对照输出，检查对齐和长度。
4. 增加 manifest、阶段缓存、失败恢复和独立 attempt。
5. 增加关键接口测试，再形成单命令执行入口。

未来只为容易破坏音频或实验结论的边界编写必要测试。

| 测试场景 | 要验证的行为 |
| --- | --- |
| 48 kHz 与 44.1 kHz 往返转换 | 时间位置按秒正确换算；已知起音点不发生累积偏移 |
| 带停顿和重叠的切片重建 | 保留原始起点与静音；重叠区域不重复相加造成音量突增 |
| 只替换参考录音 | 转录、生成和生成歌曲分离可复用；换声及混音失效重跑 |
| 子进程失败、输出缺失或文件损坏 | 不标记成功，不覆盖上一份通过的产物，可以进入新 attempt |
| 恢复一项待人工复核的任务 | 不将 needs_review 自动改为 succeeded |

未来命令接口拟为 `music-cover preflight`、`music-cover run`、`music-cover resume` 和 `music-cover inspect`；这些命令目前不存在。首版不需要数据库、HTTP 服务或任务队列。

正式验收保留整个 run 目录，尤其是输入清单、实际参数、模型身份、原始生成、双轨、换声前后人声、重混对照、最终音频、日志和评估记录。用于演示的压缩音频从归档 WAV 另行导出，不覆盖实验母文件。
